# 温室监控系统前端演示版设计

## 目标

将现有 `greenhouse_dashboard.tsx` 修复并整理为可直接运行的前端演示项目。第一阶段使用模拟传感器数据，重点交付简洁、美观、响应式且便于后续接入真实 API 的监控界面。

## 范围

- 使用 Vite、React 和 TypeScript 建立完整工程。
- 使用 Tailwind CSS 实现现有轻量化视觉风格。
- 使用 Recharts 展示趋势和统计图表，使用 Lucide React 提供图标。
- 提供 Dashboard 首页、传感器列表、响应式左侧导航和移动端抽屉。
- Dashboard 展示温度、空气湿度、土壤湿度、光照强度、环境趋势、区域统计及设备健康状态。
- 传感器页展示设备名称、类型、区域、实时值和在线状态。
- 模拟数据每五秒更新一次，数据结构与未来 API 返回模型隔离。
- 气候控制和系统设置保留清晰的开发中占位页。

## 非目标

- 本阶段不接入真实传感器接口。
- 不实现认证、权限管理、设备控制和告警推送。
- 不增加后端服务、数据库或部署配置。

## 架构与组件

- `App` 负责整体布局、导航状态及移动端侧栏。
- `DashboardView` 组合指标卡、趋势图、区域图表和系统状态。
- `SensorsView` 负责设备列表和状态展示。
- 模拟数据模块负责生成历史记录和周期性新读数；视图只消费统一的读数模型。
- 通用卡片、指标卡和状态徽章保持独立，以便后续复用。

第一阶段以适度拆分为原则：消除损坏或过大的单文件实现，但不引入路由、全局状态库或不必要的抽象。

## 数据流

应用启动时生成 24 小时历史数据。定时器每五秒根据上一条记录生成一条轻微波动的新记录，并维持固定长度的数据窗口。Dashboard 与传感器列表共享最新读数。未来接入 API 时，只需替换数据提供层，并保持读数字段稳定。

## 错误与边界处理

- 图表在无数据时显示空状态，避免读取不存在的最后一条记录。
- 未知设备状态使用中性样式。
- 定时器在组件卸载时清理。
- 页面在桌面、平板和手机宽度下保持可用。

## 验证标准

- 依赖可以正常安装。
- TypeScript 类型检查通过。
- Vite 生产构建通过。
- 本地开发服务可启动，页面无运行时错误。
- Dashboard、传感器页、侧栏切换和移动端菜单可正常交互。
- 页面不存在乱码、损坏标签或明显的横向溢出。
